- 2026-07-08 — Claude Code (Sonnet 5) — Fixed 2 bugs left by the NestJS migration that made the just-migrated app non-functional end-to-end: (1) `server/src/main.ts` never called `app.init()`, so no `@Controller` route was ever bound to the Express instance — every Nest-routed endpoint 404'd, only manually-registered Express routes worked. (2) `server/package.json`'s `dev` script ran the app through `tsx`/esbuild, which doesn't emit `emitDecoratorMetadata`, so NestJS's DI silently resolved every constructor-injected provider (services, repositories, guards) as `undefined`, crashing with `TypeError: Cannot read properties of undefined` on first use. Changed `dev` to build with real `tsc --watch` + `node --watch` over `dist/`, matching `build`/`start`. Updated [[architecture]] → Backend with both root causes.

Added `app.setGlobalPrefix("api")` in `main.ts` and removed the 3 hardcoded `api/` prefixes (`HealthController`, `NestAuthController`, `StripeWebhookController`) to avoid doubling to `/api/api/...`; verified `AuthModule`'s CSRF-exclude paths still match post-prefix. Also found and documented (not yet fixed) a pre-existing client/server path mismatch on admin inventory movements. Updated [[architecture]] → Backend.
